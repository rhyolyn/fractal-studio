Fractal Studio

Architectural Design Document

Date: 2026-05-28 Scope: Python UI layer + Rust bridge Version: Post-refactor

1. Executive Summary

B+

Fractal Studio is a PySide6/Qt desktop application for interactive fractal rendering and palette authoring. It wraps a Rust rendering engine (fractal_core) via a lazy-loading Python bridge and presents a seven-panel workspace: fractal viewport, palette editor, colormap editor, parameter controls, export controls, favorites gallery, and sidebar.

The codebase has undergone substantial layering work. Several improvements have been completed: MainWindowController was split into ExportController and SettingsController; adapter files were consolidated into a dedicated subdirectory; ViewportState now uses a discriminated union for formula-specific parameters; panel state machines receive their collaborators via constructor injection; and a validate() method catches unbound collaborators at startup.

Overall grade: B+ — structurally sound, some complexity debt accumulating in the middle layers. The primary risk is MainWindowSectionsState, which is approaching god-object territory.

5. Data Model

All domain objects in state.py are frozen dataclasses: immutable, hashable, and serializable. The key structural decision is the discriminated union for formula-specific parameters — invalid combinations are now unrepresentable at the type level.

9. SOLID Principles

S — Single Responsibility

Applied well:
  • ExportController, FavoritesController, ThemeController, SettingsController each own exactly one domain. The recent split of MainWindowController removed a known SRP violation.
  • state.py is pure data — its only responsibility is representing and serializing domain objects.
  • sections.py has one job: build a Qt layout from port objects.
  • persistence.py contains only file I/O logic; no business rules.
Still imperfect:
  • MainWindowSectionsState (sections/state.py) plays two roles: dependency container (20+ collaborator fields) and panel-state factory (constructs 6 panel states in bind()).
  • MainWindowFavoritesState has 13 constructor parameters — row management, selection, restoration, and persistence delegation are arguably separate concerns.

O — Open/Closed

Applied well:
  • ports.py Protocol interfaces allow new adapter implementations without modifying protocol definitions or sections.py.
  • FormulaParams discriminated union is extensible: adding a new formula type requires only a new frozen dataclass and an update to from_dict().
  • BackendProfile gives callers a clean capability contract without pattern-matching on backend internals.
Still imperfect:
  • Adding a new UI panel still requires changes in 5 places: new Protocol, new adapter, new panel state, update mediator, update layout.
  • Backend render methods are formula-specific function calls; a new formula requires extending the backend interface.

L — Liskov Substitution

Applied well:
  • Any class satisfying a port Protocol can substitute for any other implementation. sections.py cannot tell (and doesn't care) whether it holds a real adapter or a test double.
  • CoreBackend wraps None with a null-object facade; any code that calls backend methods still gets safe return values.
Still imperfect:
  • The null-object pattern is inconsistently applied: some coordinators guard with if not self._backend.available instead of relying on the null object. Callers cannot uniformly trust LSP substitutability.

I — Interface Segregation

Applied well:
  • Seven distinct port interfaces instead of one monolithic MainWindowPorts. Each panel receives exactly the interface it needs.
  • BackendPanelPorts has a single method — no unnecessary methods forced on implementers.
Mildly imperfect:
  • ColormapPanelPorts has 9 methods including two property accessors. It is wider than the others and worth watching as the colormap panel grows.

D — Dependency Inversion

Applied well:
  • The application layer depends on injected abstractions. Controllers receive repositories and services via constructor injection, never constructing their own.
  • main_window_factory.py is the explicit composition root — the only place that wires abstractions to concretions.
  • Panel state machines depend on collaborator protocols and callables, not on concrete Qt widget classes.
Still imperfect:
  • Several panel state machines accept MainWindow directly for statusBar().showMessage. A show_status: Callable[[str], None] injection would be narrower and more testable.
  • bind() creates lambda closures over self — not a DI violation, but an implicit lifecycle dependency.

10. Design Patterns

Repository Pattern

persistence.py — FavoritesRepository, SettingsRepository

Encapsulates all JSON file I/O behind a clean load/save interface. Callers never see file paths, error handling, or schema migration logic.

SOLID: SRP (persistence separate from domain), DIP (controllers accept a save callable).

Mediator

ui/sections/mediator.py — build_sections_ports()

Coordinates communication between panel sections without direct coupling. The mediator assembles the MainWindowSectionsPorts aggregate from individual adapters.

SOLID: OCP (new panels registered without modifying existing code).

Ports & Adapters (Hexagonal)

ui/sections/ports.py + adapters/

Isolates layout-building code from business logic. Protocols define the hexagon boundary; adapters bridge panel state machines to the layout builder.

SOLID: ISP, DIP, LSP.

Factory / Composition Root

main_window_factory.py — build_main_window_context()

Single location for all construction and wiring. The only place with knowledge of which concrete class implements which interface.

SOLID: DIP (rest of codebase never self-constructs dependencies).

Null Object

backend.py — CoreBackend

Allows the full UI to launch without a compiled Rust module. When fractal_core is absent, CoreBackend wraps None and returns safe defaults.

SOLID: LSP (backend callers get uniform behavior regardless of Rust availability).

Immutable Value Object

state.py — all @dataclass(frozen=True) types

Prevents accidental mutation of domain state as objects flow through layers. Snapshots, serialization, and equality are trivially correct.

SOLID: SRP (no behavior beyond representation and serialization).

Observer / Signal-Slot

PySide6 signals in viewport.py, editor.py, ui/controllers/

Decouples widget event producers from consumers. SidebarWiringCoordinator connects param-panel signals to viewport slots without either widget knowing about the other.

SOLID: OCP (new connections add without modifying widget classes).

State Machine

ui/sections/panel_state.py — 6 panel state classes

Each panel state machine encapsulates the widget references and collaborator methods for one panel's lifecycle. Adapters are thin forwarding shells over these machines.

SOLID: SRP (each panel's state is managed in exactly one class).

Discriminated Union

state.py — FormulaParams union type

Makes invalid formula parameter combinations unrepresentable at the type level. Before this pattern, all formula params coexisted as flat fields regardless of active formula.

SOLID: OCP (new formulas extend the union; existing code untouched).

Template Method (partial)

application/coordinators/ — orchestration methods

Coordinators define the orchestration skeleton (sequence of steps), delegating domain-specific operations to injected controllers and services.

SOLID: DIP (coordinators depend on abstracted controllers, not concrete logic).

11. Deficiencies

D1 — MainWindowSectionsState Is a Partial God Object

sections/state.py's MainWindowSectionsState holds 20+ named collaborators as dataclass fields, then constructs 6 panel state machines inside a ~60-line bind(). It plays two roles: dependency container and panel-state factory.

Impact: Any change to panel wiring requires modifying this single class. It accretes complexity with every new panel or feature.
Recommendation: Promote main_window_factory.py to construct panel states directly. MainWindowSectionsState should hold only panel state machine references, not upstream collaborators.

D2 — validate() Uses String Attribute Names

MainWindowSectionsState.validate() iterates a hardcoded list of string attribute names and calls getattr. This will silently miss any collaborator not in the list.

Recommendation: Generate the validation list from dataclasses.fields(), filtering by type annotation to exclude Optional fields.

D3 — No Test Markers (pytest.ini)

Six tests fail in environments without PySide6. There is no pytest.ini defining unit and integration markers. Running pytest does not produce a green result in a headless CI environment.

Impact: Contributors cannot verify pure-Python changes are correct without PySide6.
Recommendation: Add pytest.ini with unit and integration markers. Default run executes unit only.

D4 — Panel States Accept MainWindow Directly

MainWindowColormapState, MainWindowFavoritesState, and MainWindowExportState accept owner: MainWindow to call statusBar().showMessage.

Recommendation: Replace owner: MainWindow with show_status: Callable[[str], None] where that is the only usage. Reserve a window reference for cases that genuinely need a parent widget (file dialogs).

D5 — Backend Null-Object Inconsistently Applied

Some coordinators guard with if not self._backend.available; others rely on the null-object to return safe defaults. Callers cannot form a uniform mental model.

Recommendation: Commit to one approach — null object always returns safe defaults, guards removed — and document the contract.

D6 — Render Timer Has No Teardown Guard

FractalViewportWidget's QTimer can fire after the widget is destroyed during test teardown or rapid window close.

Recommendation: Connect timer.stop() to the widget's destroyed signal, or check self.isVisible() before scheduling.

D7 — ThemeWorkflowCoordinator Has a Hidden Side Effect

apply_theme_name() may persist settings as a side effect without any indication in its signature. The method name suggests a pure theme application.

Recommendation: Add persist: bool = False parameter with explicit conditional.

F1 — Async Rendering High Large Move render_fractal() to a QThread. The QTimer debounce in ViewportController is the right abstraction boundary — make it dispatch to a thread instead of calling synchronously.
