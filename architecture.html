Architectural Design

Fractal Studio is a layered PySide6 desktop app wrapped around a Rust renderer through a lazy-loading bridge. This page maps the structure, the design choices, and the debt that still deserves a raised eyebrow.

Date2026-05-28
ScopePython UI layer + Rust bridge
VersionPost-refactor

Executive summary

B+ Structurally sound, with some complexity debt building up in the middle layers. The main risk is MainWindowSectionsState, which is drifting toward god-object territory.

Fractal Studio is a PySide6/Qt desktop application for interactive fractal rendering and palette editing. It wraps a Rust rendering engine (fractal_core) with a lazy-loading Python bridge and presents a seven-panel workspace: fractal viewport, palette editor, colormap editor, parameter controls, export controls, favorites gallery, and sidebar.

The codebase has had a useful round of layering work. MainWindowController was split into ExportController and SettingsController; adapter files moved into a dedicated subdirectory; ViewportState now uses a discriminated union for formula-specific parameters; panel state machines receive collaborators through constructor injection; and validate() catches missing wiring at startup instead of waiting for runtime mischief.

Layered architecture

The architecture follows a strict unidirectional dependency rule enforced by test_import_policy.py: lower layers do not know about higher layers.

System Layers & Dependencies

RuleVerified by

persistence.py imports only state.pytest_import_policy.py

Data model

All domain objects in state.py are frozen dataclasses: immutable, hashable, and serializable. The important structural choice is the discriminated union for formula-specific parameters, which makes invalid combinations unrepresentable at the type level.

Diagram 2
Domain Object Class Hierarchy
ViewportState ◆── {StandardParams · JuliaParams · PhoenixParams · NewtonParams} · FavoriteSnapshot ◆── ViewportState

from_dict() handles both the current structured format, with a formula_params.type discriminator key, and the legacy flat format. Callers do not have to know migration happened, which is exactly how migration code should behave when it is behaving itself.

Dependency injection & factory

main_window_factory.py is the composition root. It builds the collaborators and assembles them into an immutable MainWindowContext before the UI event loop starts. Once built, the wiring is fixed and inspectable.

Diagram 3

Mediator / ports pattern

The ui/sections/ layer uses a Ports & Adapters pattern. sections.py builds the Qt layout by calling Protocol methods, without knowing the business logic, widgets, or adapter implementations.

SOLID principles

SSingle Responsibility

✓ Applied well

  • Export / Favorites / Theme / Settings controllers each own exactly one domain.
  • state.py is pure data — representation and serialization only.
  • sections.py has one job: build a Qt layout from port objects.

△ Still imperfect

  • MainWindowSectionsState plays two roles: dependency container and panel-state factory.
  • MainWindowFavoritesState has 13 constructor parameters across separate concerns.
OOpen / Closed

✓ Applied well

  • Port Protocols allow new adapters without touching sections.py.
  • FormulaParams union is extensible: add a dataclass + update from_dict().

△ Still imperfect

  • A new UI panel requires changes in 5 places (protocol, adapter, state, mediator, layout).
  • A new formula requires extending the backend interface.
LLiskov Substitution

✓ Applied well

  • Any class satisfying a port can substitute for another — real adapter or test double.
  • CoreBackend wraps None with a null-object facade returning safe values.

△ Still imperfect

  • Null-object pattern inconsistently applied — some coordinators still guard manually.
IInterface Segregation

✓ Applied well

  • Seven distinct port interfaces instead of one monolithic set.
  • BackendPanelPorts has a single method — nothing forced on implementers.

△ Mildly imperfect

  • ColormapPanelPorts has 9 methods — wider than the others; worth watching.
DDependency Inversion

✓ Applied well

  • Controllers receive repositories and services via constructor injection.
  • main_window_factory.py is the explicit composition root.
  • Panel states depend on collaborator protocols, not concrete Qt widgets.

△ Still imperfect

  • Some panel states accept MainWindow directly for statusBar() access.
  • bind() creates lambda closures over self — implicit lifecycle dependency.

Design patterns

Repository
persistence.py

Encapsulates JSON file I/O behind a load/save interface. Callers never see paths or migration logic.

SRP · DIP
Mediator
ui/sections/mediator.py

Coordinates panel sections without direct coupling. Assembles the ports aggregate from adapters.

OCP
Ports & Adapters
ports.py + adapters/

Isolates layout-building from business logic. Protocols define the hexagon boundary.

ISP · DIP · LSP
Factory / Composition Root
main_window_factory.py

Single location for all construction and wiring — the only place mapping interface to concretion.

DIP
Null Object
backend.py

Lets the full UI launch without a compiled Rust module by wrapping None with safe defaults.

LSP
Immutable Value Object
state.py

Frozen dataclasses prevent accidental mutation as objects flow through layers.

SRP
Observer / Signal-Slot
PySide6 signals

Decouples widget event producers from consumers via the wiring coordinator.

OCP
State Machine
panel_state.py

Each panel state encapsulates widget refs and collaborators for one panel's lifecycle.

SRP
Discriminated Union
state.py — FormulaParams

Makes invalid formula parameter combinations unrepresentable at the type level.

OCP
Template Method
coordinators/

Coordinators define the orchestration skeleton, delegating to injected controllers.

Deficiencies

D1MainWindowSectionsState is a partial god object

Holds 20+ named collaborators as fields, then constructs 6 panel state machines in a ~60-line bind(). That makes it both dependency container and panel-state factory, which is a lot of hats for one class.

Fix  Promote the factory to construct panel states directly; reduce this class to panel-state references only.
D2validate() uses string attribute names

Iterates a hardcoded list of attribute names with getattr, which means it can silently miss any collaborator not in the list.

Fix  Generate the list from dataclasses.fields(), filtering by type annotation.
D3No test markers (pytest.ini)

Six tests fail without PySide6. There is no marker config, so pytest is not green in headless CI.

Fix  Add pytest.ini with unit/integration markers; default run executes unit only.
D4Panel states accept MainWindow directly

Several states take owner: MainWindow only so they can call statusBar().showMessage.

Fix  Replace with a narrow show_status: Callable[[str], None] injection.
D5Backend null-object inconsistently applied

Some coordinators guard with if not self._backend.available; others rely on the null object. Both can work, but mixing them makes the contract fuzzier than it needs to be.

Fix  Commit to one approach and document the contract.
D6Render timer has no teardown guard

The viewport's QTimer can fire after the widget is destroyed during teardown or a fast close.

Fix  Stop the timer on the destroyed signal, or check isVisible() before scheduling.
D7ThemeWorkflowCoordinator has a hidden side effect

apply_theme_name() may persist settings without saying so in its signature. Sneaky side effects are rarely as charming as they think they are.

Fix  Add an explicit persist: bool = False parameter.
